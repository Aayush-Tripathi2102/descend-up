# DescendUp — static demo

A separate, fully fictional demo of the original `descendup` marketing site and `dashboard-descendup` dashboard. The originals are untouched. Existing layouts, styles, images, and components are retained; the dashboard's previously empty Analyze, Insights, AI Assistant, and Settings routes now contain working demo examples.

## Run

Requires Node.js 20.9+ and npm.

```sh
git clone https://github.com/Aayush-Tripathi2102/descend-up.git
cd descend-up
npm ci
npm run build
npm start
```

- Marketing: http://localhost:3000
- Dashboard login: http://localhost:3001/login/
- Click **GO TO CONSOLE**, then **Continue with demo account**. No credentials or Google account are needed.
- Development alternative: `npm run dev` starts both Next.js dev servers on the same ports.

`npm start` serves only the exported static files, not a Next.js application server. Both `marketing/out` and `dashboard/out` can instead be hosted by any static web host. Use a web server, not `file://`, to open the exports.

## What works

- Marketing pages, pricing, FAQs, navigation, and channel analysis (enter any handle).
- Browser-local fake login/logout and a populated Pro workspace for **Alex Morgan / Alex Creates**.
- Dashboard statistics, sparklines, 7/30/90-day sample reporting, notifications, and theme switching.
- Channel reports, sample video analysis, recommendations, and simulated metadata application.
- Applied video title/description/tag changes persist across refreshes in this browser.
- Insights filters and saved insights, a prewritten-response assistant, and saved preferences.
- Settings → **Reset demo data** restores the sample state and signs out.

All results are fictional. No account is connected, no email is sent, no payment is taken, and nothing is published to YouTube. Assistant responses are deterministic examples, not generated by an AI service. The demo login is a visual workflow, **not security**. There are no API routes, database modules, OAuth credentials, tokens, or backend integrations in this copy. Standard static HTML, JS, CSS, image, font, and navigation-payload requests are still required to load pages.

## Hosting on other URLs

Before building, set these optional public configuration values (not secrets):

- Marketing build: `NEXT_PUBLIC_PRO_URL=https://your-dashboard.example`
- Dashboard build: `NEXT_PUBLIC_MARKETING_URL=https://your-marketing.example`

Defaults are `http://localhost:3001` and `http://localhost:3000`. Host each exported `out` directory at its own domain/root. Trailing-slash routes use directory `index.html` files. No environment file, database, or API key is required.

## Production (Vercel)

- Marketing: https://descend-up-one.vercel.app
- Dashboard: https://descend-up-console.vercel.app/login/

The same GitHub repository is connected to two Vercel projects. Each project deploys `main` automatically:

| Project | Root Directory | Public environment variable |
| --- | --- | --- |
| `descend-up` | `marketing` | `NEXT_PUBLIC_PRO_URL=https://descend-up-console.vercel.app` |
| `descend-up-console` | `dashboard` | `NEXT_PUBLIC_MARKETING_URL=https://descend-up-one.vercel.app` |

Both projects use Node.js 22, install with `npm ci`, build with `npm run build`, and publish `out`. The per-app `vercel.json` files configure static hosting and trailing-slash routing. Keep **Include source files outside of the Root Directory** enabled so Vercel can use the root workspace manifest and lockfile. Public URL variables are set in Vercel for production, preview, and development; local builds still default to localhost.

GitHub Actions runs type checking, linting, and both production builds on pushes to `main` and pull requests. Do not commit `.env*`, `.vercel`, build output, or credentials.

## Original connection

Originally, marketing uses Google OAuth, writes users and YouTube tokens into a shared Neon/Drizzle database, sets a shared-domain JWT session cookie, and redirects to the dashboard. The dashboard reads that session/database and calls local API routes for YouTube analytics and optimization. This demo replaces the entire chain with static sample fixtures and localStorage. The two sites remain connected via navigation; login state lives only on the dashboard origin.
